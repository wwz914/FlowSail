## 0. 摘要（TL;DR）

FlowSail 目前是一个**能画、能连、能编、能配**的画布内核：可缩放平移、从锚点拖拽创建连线并校验、拖动节点、选择删除、撤销重做、从面板创建节点；节点有类型、有参数，配置能改也能撤销。但流程文档还不能存成可迁移的一等公民，参数也还不能引用上游输出，更没有运行与调试。

对标扣子工作流编辑器，一个"能用的"AI 工作流编辑器至少需要四层能力：

1. **画布交互闭环**：缩放、平移、连线创建、选择、删除、撤销重做；
2. **节点体系**：节点类型注册表 + 开始/结束/大模型/插件/条件/代码等基础节点；
3. **数据与配置**：节点配置面板、参数表单、变量引用、文档级序列化；
4. **运行与调试**：执行接口抽象、试运行、运行记录、错误态可视化。

本文定义 v1 的产品边界与功能需求，[ROADMAP](./ROADMAP.md) 给出初期基础能力建设的落地顺序与验收标准。**建议先补齐工程地基（测试/类型/构建），再按 M1→M2→M3 推进**，否则每加一个交互都会引入回归。

## 1. 背景与问题

### 1.1 问题

搭建 AI 应用时，"把多个模型调用、插件、条件分支串成可执行流程"是高频需求。扣子、Dify、n8n 等产品都提供了可视化编排能力，但它们的编辑器内核大多：

- 与自家平台绑定（模型、插件、发布渠道强耦合），难以嵌入第三方产品；
- 体量偏大、样式与框架强绑定，接入成本高；
- 即使开源，数据模型与执行语义也由平台定义，二次开发仍需接受既有抽象。

### 1.2 机会

做一个**轻量、可嵌入、与执行后端解耦**的工作流画布内核：

- 数据层框架无关（`@system` 只有类型与纯函数）；
- 视图层是标准 React 组件，可受控使用，样式隔离；
- 工作流文档是纯 JSON，可被任意后端执行器消费；
- 允许宿主自定义节点类型、面板、执行器。

### 1.3 当前进展（代码现状）

仓库是 pnpm monorepo，三个包：

| 包 | 定位 | 现状 |
| --- | --- | --- |
| `packages/system`（包名 `@system`） | 框架无关数据层 | `Node`/`Edge`/`Workflow` 类型 + `applyNodeChanges`/`applyEdgeChanges` 纯函数，支持 add / remove / replace / position / select；`document.ts` 提供文档模型（`createWorkflow`/`normalizeWorkflow`/`migrateWorkflow`/`validateWorkflowDocument`/`serializeWorkflow`/`parseWorkflowDocument`） |
| `packages/react`（包名 `react`，示例中以 `reactflow` 引入） | React 画布实现 | `ReactFlow` 负责视口、选择、删除、撤销重做与节点创建，并支持受控 `workflow` + `onChange`；`NodeCard` 承载节点拖拽与卡片视觉；`EdgeRenderer` 渲染/选中贝塞尔曲线；zustand store 持有单份 `Workflow` 快照；另有变量引用解析、文档级校验、导入导出与工具栏、校验面板、schema 预览等模块 |
| `packages/example`（private） | Vite 演示应用 | 三栏布局（工具栏 / 节点面板 / 画布 / 配置面板 / 校验面板），以受控模式演示带条件分支、变量引用与文档导入导出的流程 |

**已经具备**：视口缩放平移与适应画布、锚点连线创建与校验、贝塞尔连线渲染、节点拖拽、分层渲染与点阵网格、单选/多选与删除、快照式撤销重做、左侧节点面板、节点卡片图标与类型徽标、节点类型注册表（6 类内置节点 + 宿主自定义类型）、条件分支与分支标签、参数配置面板、工作流文档模型（`id`/`name`/`version`/`meta`）与 schema 版本迁移、变量引用（`{{nodeId.field}}`）解析与标红、变量选择器、输入/输出 schema 预览、文档级校验、JSON 导入导出、受控 `workflow` + `onChange` API、顶部工具栏。

**尚不具备**：框选、复制粘贴、节点重命名、网格吸附、自动布局、小地图、主题与可访问性、发布流程与包改名、运行调试（试运行 / 运行记录 / 运行态，属 M3）、运行期的输入/输出快照（属 M3）。

**工程基线**：v1.0 修复了原有类型错误与 Hooks 违规，落地 Vitest、`pnpm build`/`typecheck`/`lint` 与 GitHub Actions CI；v1.1 补充了选择、删除、撤销重做、节点创建与 props 同步边界的测试；v1.3 补充了节点类型注册表、参数 schema 校验、多出口连线与参数入栈的测试；v1.4 补充了文档模型与迁移、变量引用解析与作用域推导、上游拓扑推导、文档级校验、导入导出往返与受控模式的测试，`pnpm test` 共 184 个用例。M2 的完整任务清单见 [ROADMAP §2](./ROADMAP.md#2-阶段规划)，v1.3 的切分见 [ROADMAP §8](./ROADMAP.md#8-v13-范围)，v1.4 的切分见 [ROADMAP §9](./ROADMAP.md#9-v14-范围)。

**结论**：M1 的"能编"闭环已经成立——可以从空画布创建节点、连线、选中、删除并撤销/重做；v1.3 进入 M2 的前半段（节点注册表、6 类内置节点、条件分支、参数配置面板），把产品从"能编"推进到"能配"；v1.4 收口 M2 的后半段（文档模型、变量引用、文档级校验、工具栏），把产品推进到"能存、能引用、能校验"。M2 至此完成，M3（能跑）以 v1.4 定下的文档 schema 为基础开工。范围见 [ROADMAP §8](./ROADMAP.md#8-v13-范围) 与 [§9](./ROADMAP.md#9-v14-范围)。

## 2. 目标与非目标

### 2.1 产品目标（v1）

1. 宿主能在一个页面里嵌入 FlowSail，编辑一份可序列化的工作流文档；
2. 用户能在画布上完成"加节点 → 连线 → 配参数 → 引用上游变量"的完整编辑闭环；
3. 用户能对整条工作流或单个节点发起试运行，并在画布/日志中看到结果与错误；
4. 编辑器内核不依赖任何具体模型、插件市场或后端服务；
5. 公开 API 类型完整、行为可预测，且有自动化测试兜底。

**成功指标（v1 验收口径）**：

- 从 0 到"跑通一个开始→大模型→结束"的示例，新用户按 README 操作 ≤ 10 分钟；
- 画布在 300 节点 / 500 连线下拖拽、缩放保持流畅（目标 ≥ 50fps）；
- 核心数据层与交互逻辑单测覆盖率 ≥ 70%；
- 宿主按文档自定义一种节点类型，改动不超过 1 个文件。

### 2.2 非目标（v1 明确不做）

| 不做 | 原因 |
| --- | --- |
| 模型接入、Prompt 托管、计费 | 与执行后端强绑定，不属于编辑器内核；通过 `Runner` 接口外置 |
| 插件市场 / 插件运行时 | 生态能力，依赖后端与审核体系 |
| 多人实时协作、评论、权限 | 需要协同基础设施，投入产出比暂不匹配 |
| AI 自动生成工作流 | 依赖模型与提示词工程，远期探索 |
| 像素级复刻扣子视觉 | 学习交互与信息架构即可，保留自有设计语言 |
| 自建后端服务 | v1 全部能力均可在浏览器内完成；持久化交给宿主 |
| 移动端适配 | 编辑场景以桌面端为主，v1 不做 |

## 3. 用户与场景

### 3.1 用户角色

| 角色 | 描述 | 关键诉求 |
| --- | --- | --- |
| 集成开发者（主要） | 在自家产品中嵌入画布，需要 API 稳定、可扩展 | 类型安全、受控用法、自定义节点、无样式污染 |
| 工作流作者（次要） | 用画布编排流程的产品/运营同学 | 操作直观、连线清晰、报错可定位 |
| 平台维护者 | 维护节点库与执行器 | 节点注册机制、文档 schema 可演进 |

### 3.2 核心场景

1. **搭一条最小流程**：拖入开始节点 → 大模型节点 → 结束节点，连线，保存。
2. **加条件分支**：在链路上插入条件节点，配置两个出口（是/否），分别接不同下游。
3. **引用上游变量**：在大模型节点的 Prompt 里插入开始节点的查询变量（如 `{{node_start.query}}`），画布上能看到引用关系。
4. **试运行排错**：点击试运行，节点依次高亮；某节点失败时变红，右侧面板显示错误与输入快照。
5. **嵌入宿主**：宿主用受控模式接管 `workflow` 状态，保存到自己的后端；换一套主题色。

## 4. 竞品对标：扣子工作流编辑器

### 4.1 对标依据

- 用户提供的扣子编辑器截图（群内消息，2026-11-03）：画布 + 右侧节点配置面板 + 底部运行面板的三栏结构，含插件节点、条件分支、分支标签、单节点测试、输入/输出 JSON 预览、缩放控制、试运行/取消运行。
- 扣子公开文档与产品体验整理的能力清单（节点类型部分为 v0.1 归纳，**待复核**）。

### 4.2 能力拆解

**A. 编辑器外壳**

- 顶部工具栏：撤销/重做、试运行、取消运行、自动布局、分享、协作、**部署**（主 CTA）；支持多标签页/预览。
- 右侧面板：节点配置——标题、代码视图、全屏、关闭；节点描述；**测试**按钮；输入 JSON；输出 JSON（含字段类型说明）。
- 底部面板：终端 / 运行记录 / 输出 三个页签，运行记录可切换；展示试运行沙箱资源占用（CPU / 内存）与释放入口。
- 画布左下角：缩放比例（如 52%），可下拉选择。

**B. 画布**

- 点阵网格背景；节点卡片（图标 + 名称 + 类型徽标，插件节点带来源徽标）。
- 条件节点呈分支结构，出口带**分支标签**（如"结果""查询天气""生成播报"）。
- 选中节点后有浮动工具条（代码视图、引用等操作）。
- 连线为曲线，端口固定在节点上下边缘。

**C. 节点体系（扣子）**

开始、结束、大模型、插件（官方/自定义工具）、子工作流、代码、知识库检索/写入、文本处理、选择器（条件）、意图识别、循环、批处理、数据库（增删改查）、变量赋值/读取、HTTP 请求、消息、图像/视频生成等，共 20+ 种。

**D. 数据流**

- 节点参数可用 `{{节点.字段}}` 引用上游输出；
- 引用选择器按拓扑顺序过滤可选变量，并做类型校验；
- 支持会话变量与系统变量。

**E. 运行与调试**

- 整体试运行 + 单节点测试；
- 运行记录含每个节点的输入/输出快照、耗时、状态；
- 异常处理：重试、忽略、异常分支；错误节点在画布上高亮。

**F. 发布与协作（远期）**

- 发布为 API / Bot 插件；版本管理与回滚；多人协作与评论。

### 4.3 能力矩阵与取舍

| 能力域 | 扣子 | FlowSail v1 目标 | 说明 |
| --- | --- | --- | --- |
| 画布缩放/平移 | ✅ | ✅ 做（P0） | 编辑器基本盘 |
| 锚点与拖拽连线 | ✅ | ✅ 做（P0） | 当前完全缺失 |
| 条件分支 + 分支标签 | ✅ | ✅ 做（P1） | 条件节点带命名出口 |
| 选择/多选/删除 | ✅ | ✅ 做（P0） | 交互闭环必需 |
| 撤销/重做 | ✅ | ✅ 做（P0） | 靠文档快照 + 历史栈 |
| 节点配置面板 | ✅ 丰富 | ✅ 做（P0，简化） | v1 只做参数表单 + 变量引用 |
| 节点单测 | ✅ | ✅ 做（P1） | 依赖 Runner 接口 |
| 运行记录/日志 | ✅ | ✅ 做（P1） | 简化版：节点级时间线 |
| 20+ 节点类型 | ✅ | ⚠️ 只做 6 类（P0） | 其余靠注册表扩展，避免内核膨胀 |
| 子工作流 / 循环 / 批处理 | ✅ | ⏳ P2 | 需要执行语义支持 |
| 知识库 / 数据库 / 多媒体节点 | ✅ | ❌ 不做 | 与后端绑定，交给宿主扩展 |
| 部署 / 发布 API | ✅ | ⚠️ 只暴露 `onExport`（P1） | 发布链路由宿主实现 |
| 多人协作 / 评论 | ✅ | ❌ 不做 | 非目标 |
| 自动布局 / 小地图 | 部分 | ⏳ P2 | 体验增强；小地图是否具备待复核 |

### 4.4 关键取舍结论

1. **做编辑器内核，不做执行平台**：`Runner` 定义成接口，v1 提供 Mock Runner 支撑调试 UI；真实执行由宿主注入。
2. **节点类型宁少勿多**：v1 只内置开始、结束、大模型、插件（工具占位）、条件、代码六类，其余通过 `nodeTypes` 注册，避免内核被业务语义污染。
3. **配置面板先窄后宽**：v1 只支持"参数表单 + 变量引用 + 输入输出预览"，节点专属编辑器（如 Prompt 编排器、代码编辑器）由宿主通过插槽扩展。
4. **信息架构对齐扣子，视觉不照搬**：三栏布局 + 底部运行面板是对标重点，配色与组件遵循轻量原则。

## 5. 产品定位与设计原则

**一句话定位**：FlowSail 是一个可嵌入 React 应用的 AI 工作流画布编辑器内核。

设计原则：

1. **数据先行**：`Workflow` JSON 是唯一事实源，一切交互都是对文档的变换；文档可序列化、可版本化、可校验。
2. **内核可嵌入**：受控/非受控两种用法；不污染全局样式；不假设路由、状态库或后端。
3. **渐进增强**：静态画布 → 交互闭环 → 配置与变量 → 运行调试，每层独立可用。
4. **类型即契约**：strict TypeScript，公开类型稳定；破坏性变更走大版本。
5. **状态可见**：运行态、错误态、校验态直接呈现在画布上，而不是只藏在日志里。

## 6. 功能需求

### 6.1 优先级定义

| 优先级 | 含义 |
| --- | --- |
| **P0** | v1 必须完成，缺失则产品不可用 |
| **P1** | v1 应该完成（或 v1.1），影响可用性与体验 |
| **P2** | 远期增强，不阻塞发布 |

### 6.2 画布与视口（FR-C）

- **FR-C1 图面渲染**（P0）：点阵网格背景；HTML 节点层与 SVG 连线层分离；支持自定义背景与主题变量。
  *验收*：300 节点渲染首屏 < 500ms；缩放时网格随视口变化。
- **FR-C2 缩放**（P0）：滚轮/触控板缩放，范围 25%–200%，以指针位置为锚点；左下角显示比例并可重置 100%。
  *验收*：缩放后指针下的图元位置不漂移。
- **FR-C3 平移**（P0）：空格 + 拖拽、中键拖拽、双指滚动；平移边界不限制（可无限延伸）。
- **FR-C4 适应画布**（P1）：一键 fit view（含内边距），空画布时按钮禁用。
- **FR-C5 视口持久化**（P1）：视口随文档保存与恢复。
- **FR-C6 小地图**（P2）：可开关的缩略图，点击跳转。
- **FR-C7 自动布局**（P2）：基于拓扑的纵向/横向布局。

### 6.3 节点体系（FR-N）

- **FR-N1 节点卡片**（P0）：图标 + 标题 + 类型徽标；常态、悬停、选中、运行中、成功、错误六态（运行态细节见 FR-N7）；宽度自适应，标题超长省略。
- **FR-N2 拖拽移动**（P0）：拖动更新节点位置；多选时整体移动；拖动时关联连线实时跟随。
  *验收*：拖动 60fps；松手后位置持久化。
- **FR-N3 节点类型注册表**（P0）：`type → { 渲染器, 图标, 默认数据, 锚点定义, 参数 schema }`；宿主可注册自定义类型。
- **FR-N4 内置节点最小集**（P0）：开始、结束、大模型、插件（工具占位）、条件、代码，共 6 类。
- **FR-N5 节点操作**（P0）：删除（Delete/Backspace）、复制/粘贴（P1）、重命名（P1）。
- **FR-N6 节点选中工具条**（P1）：选中后浮动操作（复制、删除、运行到此节点）。
- **FR-N7 节点状态可视化**（P1）：idle / running / success / error / skipped 五态。
- **FR-N8 节点分组/注释**（P2）：框选分组、便签注释。

### 6.4 连线与分支（FR-E）

- **FR-E1 锚点**（P0）：每个节点声明输入/输出锚点；命中区域 ≥ 12px；悬停高亮并提示可连接。
- **FR-E2 创建连线**（P0）：从输出锚点按下拖到输入锚点创建；拖拽过程显示预览曲线；非法目标高亮为错误色。
- **FR-E3 连线渲染**（P0）：贝塞尔曲线 + 箭头；hover/选中加粗高亮；曲线避开节点（P1）。
- **FR-E4 连线校验**（P0）：禁止自连、重复连线、输入锚点重复连接（默认单入）；类型不兼容提示（P1）。
- **FR-E5 删除连线**（P0）：选中后删除；从锚点反向拖出断开（P1）。
- **FR-E6 分支标签**（P1）：条件/意图节点的出口带可编辑标签，标签显示在连线上。
- **FR-E7 连线编辑**（P2）：拖拽控制点调整路径、正交路由。

### 6.5 配置与变量（FR-P）

- **FR-P1 配置面板**（P0）：选中节点时右侧展开；展示名称、描述、参数表单；未选中时显示工作流级配置。
- **FR-P2 参数控件**（P0）：string / number / boolean / select / json 五类；必填校验与错误提示。
- **FR-P3 变量引用**（P0）：参数值支持 `{{nodeId.field}}`；提供变量选择器，只列拓扑上游节点；引用非法时标红。
- **FR-P4 输入/输出预览**（P1）：展示节点输入快照与输出 schema（类型 + 描述）。
- **FR-P5 单节点测试**（P1）：面板内"测试"按钮，使用手填输入执行当前节点并展示输出。
- **FR-P6 文档级校验**（P1）：孤立节点、悬空连线、必填缺失、引用失效，汇总为问题列表并可定位。

### 6.6 运行与调试（FR-R）

- **FR-R1 Runner 接口**（P1）：`run(workflow, { onNodeStart, onNodeEnd, signal })`；v1 提供 Mock Runner（按拓扑顺序延迟返回假数据）。
- **FR-R2 整体试运行**（P1）：按钮触发、进度反馈、可取消；运行中禁止编辑或给出提示（待确认）。
- **FR-R3 运行记录**（P1）：底部面板按节点展示状态、耗时、输入/输出；支持复制。
- **FR-R4 运行态联动**（P1）：画布节点颜色/边框随运行状态变化；点击日志行定位节点。
- **FR-R5 异常策略**（P2）：重试次数、忽略错误、异常分支。
- **FR-R6 资源与性能观测**（P2）：节点耗时、内存占用（对标扣子的沙箱资源展示，简化实现）。

### 6.7 数据模型与持久化（FR-D）

- **FR-D1 工作流文档**（P0）：`Workflow` 含 `id/name/version/nodes/edges/viewport/meta`；可 `JSON.stringify`/`parse`；`version` 用于迁移。
- **FR-D2 变更合并**（P0）：`applyNodeChanges`/`applyEdgeChanges` 支持 `add/remove/replace/select/position` 等 change 类型；纯函数、不可变。
- **FR-D3 导入/导出**（P1）：导出 JSON 文件；导入时校验 schema 并给出可读错误。
- **FR-D4 撤销/重做**（P0）：撤销栈 + 重做栈，容量可配（默认 50）；拖拽合并为一次历史。
- **FR-D5 持久化适配器**（P2）：localStorage / 远程保存的可选实现。

### 6.8 编辑器外壳（FR-U）

- **FR-U1 三栏布局**（P0）：顶部工具栏 + 画布 + 右侧配置面板；底部运行面板可折叠（P1）。
- **FR-U2 工具栏**（P0）：撤销、重做、试运行、适应画布、导出；按钮态随可用性禁用。
- **FR-U3 快捷键**（P1）：Delete、Ctrl/Cmd+Z、Ctrl/Cmd+Shift+Z、Ctrl/Cmd+C/V、Ctrl/Cmd+A、空格平移、Esc 取消。
- **FR-U4 主题**（P1）：亮/暗两套 CSS 变量，宿主可覆盖。
- **FR-U5 多标签**（P2）：同时编辑多个工作流文档。

### 6.9 扩展与集成（FR-X）

- **FR-X1 受控/非受控**（P1）：受控模式由宿主持有 `workflow` 并在 `onChange` 中更新；非受控模式内部维护。
- **FR-X2 自定义节点**（P1）：通过 `nodeTypes` 注册渲染与参数 schema。
- **FR-X3 事件回调**（P1）：`onNodeClick`、`onEdgeCreate`、`onChange`、`onSelectionChange`。
- **FR-X4 样式隔离**（P0）：组件样式挂在 `.flowsail` 命名空间下，不写全局选择器。
- **FR-X5 SSR 安全**（P2）：不访问 `window`/`document` 直到挂载。

## 7. 交互规范

### 7.1 布局

编辑器整体分为四个区域：

| 区域 | 内容 |
| --- | --- |
| 顶部工具栏 | 撤销、重做、试运行/取消运行、适应画布、导出、主题切换 |
| 画布 | 点阵网格；节点与连线；左下角缩放比例；可选小地图 |
| 右侧面板 | 节点名称与描述、参数表单、变量引用、输入/输出预览、测试按钮；未选中时显示工作流级配置 |
| 底部面板 | 运行记录（节点、状态、耗时、输入、输出），可折叠 |

### 7.2 选择与多选

| 操作 | 行为 |
| --- | --- |
| 单击节点/连线 | 单选，打开配置面板 |
| Shift + 单击 | 追加/取消选择 |
| 框选（P1） | 选中矩形内节点 |
| 单击空白 | 取消选择，面板回到工作流级 |
| Delete / Backspace | 删除选中节点及其连线 |

### 7.3 拖拽与吸附

- 拖动阈值 3px 后进入拖拽态，避免误触；
- 网格吸附 8px（P1，可开关）；
- 拖动节点时，其相邻连线端点实时跟随；
- 拖拽结束才写入历史栈（一次拖拽 = 一次撤销）。

### 7.4 连线

1. 鼠标悬停节点显示锚点；
2. 从输出锚点按下，曲线跟随指针；
3. 悬停合法输入锚点时高亮为可连接态，非法时为禁用态并提示原因；
4. 松手创建连线并打开连线标签编辑（条件节点）；
5. Esc 或松手在空白处取消。

### 7.5 快捷键（默认映射）

## 8. 数据模型草案

> 草案，供实现参考；最终以 `packages/system` 导出的类型为准。

```ts
// 示意用，省略 React / ParamSchema / NodeProps 等类型导入
interface Workflow {
  id: string;
  name: string;
  version: 1;
  nodes: WorkflowNode[];
  edges: WorkflowEdge[];
  viewport: { x: number; y: number; zoom: number };
  meta?: Record<string, unknown>;
}

interface WorkflowNode {
  id: string;
  type: string;            // 注册表中的节点类型
  position: { x: number; y: number };
  data: Record<string, unknown>;
  selected?: boolean;
  measured?: { width: number; height: number }; // 运行时测量，不参与持久化
}

interface Handle {
  id: string;
  type: 'source' | 'target';
  position: 'top' | 'bottom' | 'left' | 'right';
}

interface WorkflowEdge {
  id: string;
  source: string;
  sourceHandle?: string;
  target: string;
  targetHandle?: string;
  label?: string;          // 条件分支标签
  type?: string;           // 曲线类型
  selected?: boolean;
}

type NodeChange =
  | { type: 'add'; node: WorkflowNode }
  | { type: 'remove'; id: string }
  | { type: 'replace'; id: string; node: WorkflowNode }
  | { type: 'position'; id: string; position: { x: number; y: number } }
  | { type: 'select'; id: string; selected: boolean };
```

节点类型注册表示例：

```ts
interface NodeTypeDefinition {
  type: string;
  label: string;
  icon?: React.ComponentType;
  defaultData: Record<string, unknown>;
  handles: Handle[];
  params?: ParamSchema[];
  render?: React.ComponentType<NodeProps>;
}
```

**兼容性**：`Workflow.version` 递增时提供 `migrate(doc)`；编辑器不读取未知字段，但导出时原样保留（避免宿主扩展信息丢失）。

## 9. 非功能需求

| 维度 | 要求 |
| --- | --- |
| 性能 | 300 节点 / 500 连线：拖拽与缩放 ≥ 50fps；首屏渲染 < 500ms；缩放不重排全部节点 |
| 体积 | 画布内核 gzip 后 < 60KB（不含宿主自身依赖） |
| 类型 | strict TypeScript，导出 `.d.ts`；公开 API 无 `any` |
| 兼容 | Chrome / Edge / Safari / Firefox 最近两个大版本；React 18/19 |
| 可访问性 | 画布与面板可 Tab 到达；关键操作有 `aria-label`；不依赖颜色单一传达状态 |
| 可测试 | 数据层纯函数 100% 可测；交互行为有组件级测试；不依赖真实浏览器也可跑核心逻辑 |
| 可嵌入 | 无全局副作用、无全局样式选择器；组件可卸载干净 |
| 国际化 | v1 中文文案，文案集中管理，预留 i18n 能力 |
| 安全 | 不执行工作流中的任意代码；代码节点执行由 Runner 在沙箱中负责 |

## 11. 风险与开放问题

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 无测试 + 既有 Hooks 违规 | 每次加交互都可能引入回归 | ✅ v1.0 已解决：Hooks 修复、Vitest 与 CI 落地；后续交互需同时补测试 |
| 执行引擎缺失 | 调试体验只能是 Mock，真实价值后置 | `Runner` 接口先行，v1 用 Mock；不绑定具体后端 |
| 节点类型膨胀 | 内核被业务语义污染，包体积失控 | 注册表 + 最小内置集；业务节点由宿主扩展 |
| 文档与代码漂移 | 新人按 README 无法跑通 | README 中的命令必须实测；CI 增加文档链接检查（P2） |
| `packages/react` 包名与 npm `react` 同名 | 依赖解析易混淆 | 发布前改名为 `@flowsail/react`（见 §11 决策）；重命名随 M4 D-1 一起执行 |
| 构建链路缺失 | 无法产出可发布的产物 | ✅ v1.0 已解决：Vite library mode + `tsc` 产出 `dist`；发布流程留到 M4 |

**已确认决策（2026-11-03，wwz914）**：

| 问题 | 结论 | 影响 |
| --- | --- | --- |
| 产品形态 | 开源组件库（可嵌入 React 组件库），不做内部平台底座 | 发布按开源库语义化版本推进，API 兼容按公开库要求处理 |

## 12. 术语表

| 术语 | 说明 |
| --- | --- |
| 工作流（Workflow） | 一份由节点和连线组成的可执行流程文档 |
| 节点（Node） | 工作流中的一个处理单元，有类型、位置、参数 |
| 锚点（Handle） | 节点上用于连接连线的输入/输出端口 |
| 连线（Edge） | 连接两个锚点的有向关系，可有分支标签 |
| 变量引用 | 形如 `{{nodeId.field}}` 的表达式，运行时解析为上游输出 |
| Runner | 执行工作流的接口实现，由宿主注入或使用内置 Mock |
| 画布（Canvas） | 可缩放平移的二维编辑平面 |
