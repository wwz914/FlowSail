# FlowSail 初期路线图（ROADMAP）

> 配套文档：[产品 PRD](./PRD.md) · [README](../README.md) · [AGENTS.md](../AGENTS.md)
> 适用基线：`main` @ `cb3afdd`（第一轮合并后，2026-11-03）
> 本文回答两个问题：**对标扣子工作流编辑器，初期该先建哪些基础能力、按什么顺序**；以及**下一轮（第二轮）具体做什么**（§7，待确认）。

---

## 0. 一页结论

当前项目缺的不是"更多节点类型"，而是**能让编辑器跑起来的地基**。按投入产出排序，初期应依次完成：

1. **工程地基**（测试、类型、构建、CI）——不先做，后面每加一个交互都在裸奔；
2. **画布交互闭环**（缩放平移、锚点连线、选择删除、撤销重做）——这是"编辑器"与"画布"的分水岭；
3. **节点体系与配置**（类型注册表、6 类基础节点、配置面板、变量引用）——这是"能编排"的前提；
4. **运行与调试**（Runner 接口、试运行、运行记录）——这是"能验证流程正确"的关键；
5. **交付能力**（文档、示例、构建产物、发布）——决定别人能不能用起来。

扣子的 20+ 节点类型、知识库、数据库、发布 API、多人协作**都不在初期范围**，靠注册表与接口外置。

第一轮（2026-11-03 合并，PR #13）已完成第 1 项（工程地基）和第 2 项的一部分（视口、锚点、连线创建与校验）。第二轮按 §7 收口第 2 项——选择、删除、撤销重做与节点创建入口——再进入第 3 项。

## 1. 现状盘点

| 能力域 | 现状 | 缺口 | 初期优先级 |
| --- | --- | --- | --- |
| 数据层 | `Node`/`Edge` 类型 + 两个按 id 浅合并的纯函数 | 变更类型不全（无 add / remove / select / position）、无文档 schema、无校验/迁移 | P0（R2-1） |
| 画布渲染 | HTML 节点层 + SVG 曲线层 + 点阵网格；层序与指针事件已分离 | 节点卡片只有标题，无图标、类型徽标 | P0（R2-5） |
| 视口 | 指针锚点缩放（25%–200%）、空格/中键平移、比例显示、适应画布 | 视口未随文档持久化 | ✅ 已完成（C-1~C-3） |
| 节点交互 | 指针拖拽移动，拖拽逻辑在 `NodeCard` 顶层 | 选择、多选、删除、复制、吸附 | P0（R2-2 / R2-3） |
| 连线交互 | 创建、自连/重复/单入校验、贝塞尔 + 箭头、hover 高亮、预览曲线 | 删除、选中高亮、分支标签编辑 | P0（R2-3） |
| 节点体系 | 仅 `data.label`，`Node.type` 未使用 | 注册表、内置节点、图标、端口定义 | P0（M2） |
| 配置面板 | 无 | 参数表单、变量引用、输入输出预览 | P0（M2） |
| 撤销重做 | 无 | 历史栈、拖拽合并 | P0（R2-4） |
| 节点创建 | 无：节点只能由宿主通过 props 传入 | 画布内的节点添加入口 | P0（R2-6，M1 DoD 缺口） |
| 运行调试 | 无 | Runner 接口、试运行、日志、状态 | P1（M3） |
| 文档序列化 | 无 | 导出/导入、版本迁移 | P1（M2） |
| 工程地基 | Vitest（30 个用例）、`pnpm build`/`typecheck`/`lint`、GitHub Actions CI | 无覆盖率门禁、无性能基准 | ✅ 已完成（G-1~G-6） |
| 主题/可访问性 | 无 | CSS 变量、键盘可达 | P1/P2 |

**一句话**：第一轮补上了地基与"能画"的部分；现在能画、能连，但还不能删、不能撤销，也不能在画布上新建节点——"能编"的闭环还差最后一圈。

## 2. 阶段规划

> 顺序原则：**先地基、后交互、再配置、最后运行**。每一阶段结束都应是一个可演示、可回归的版本。
> 工作量为人日粗估，按单人全职口径，误差 ±50%。

### M1：工程地基 + 可用画布（前置，约 10–14 人日）

#### 2.1 工程地基（必须先做）

| 编号 | 任务 | 为什么初期必须 | 验收标准 |
| --- | --- | --- | --- |
| G-1 | 修 `example` 的 `@system/types.ts` 解析（在 `tsconfig.app.json` 增加 `paths` 或统一导入写法） | 当前 `pnpm --filter example build` 有 8 处 TS 错误，任何类型检查都无从谈起 | `pnpm --filter example build` 的 TS 错误清零 |
| G-2 | 修 `store.setNodes` 类型（声明成 `Node[] \| ((nodes: Node[]) => Node[])`） | 类型与实现不一致，函数式更新无法通过检查 | `tsc` 通过，`NodeRenderer` 不再用 `any` |
| G-3 | 修 `NodeRenderer` 的 Hooks 违规（把节点抽成独立组件，hook 在组件顶层） | 节点数量变化会直接崩溃，后续所有节点交互都建在它上面 | 增删节点不报 "Rendered more hooks"，并有对应测试 |
| G-4 | 引入测试框架（推荐 Vitest + Testing Library）与 `pnpm test` | 仓库当前零测试，交互改动无回归保护 | 至少覆盖 `applyNodeChanges`/`applyEdgeChanges` 与一个节点渲染用例；`pnpm test` 全绿 |
| G-5 | 统一根脚本：`dev`/`build`/`test`/`lint`；修复或替换 rollup 构建 | 根 `package.json` 只有 `test`，且 rollup 因 tsconfig `module: NodeNext` 失败 | 四条命令本地可跑；构建产物能产出 |
| G-6 | CI（GitHub Actions）：install → lint → test → typecheck | 没有 CI 就没有合并门槛，文档与代码容易漂移 | PR 上自动执行，失败阻断合并 |

#### 2.2 画布交互闭环

| 编号 | 任务 | 验收标准 |
| --- | --- | --- |
| C-1 | 视口：缩放（25%–200%，指针锚点）、平移（空格/中键/双指）、比例显示与重置 | 缩放不漂移；比例与真实值一致 |
| C-2 | 适应画布（fit view），空画布禁用 | 一键框住全部节点，含内边距 |
| C-3 | 分层：HTML 节点层 + SVG 连线层 + 交互层；点阵网格背景 | 层序正确，指针事件不互相遮挡 |
| C-4 | 锚点：节点声明输入/输出锚点，悬停高亮，命中区 ≥ 12px | 6 类节点锚点位置正确 |
| C-5 | 连线创建：输出锚点拖到输入锚点，实时预览，非法目标禁用并提示 | 能搭出"开始→大模型→结束"链路 |
| C-6 | 连线渲染：贝塞尔 + 箭头 + hover/选中高亮 | 连线随节点移动实时更新 |
| C-7 | 连线校验：禁自连、禁重复、单入约束 | 非法操作有明确反馈，不产生脏数据 |
| C-8 | 选择：单选、Shift 追加、空白取消、框选（P1） | 选中态与实际选中集合一致 |
| C-9 | 删除：节点连同其连线一起删除，连线单独可删 | 删除后无悬空连线 |
| C-10 | 撤销/重做：历史栈 + 拖拽合并 + 快捷键 | 拖拽、删除、连线、参数修改均可撤销/重做 |
| C-11 | 节点卡片视觉：图标、标题、类型徽标、选中/悬停态 | 与 PRD §6.3 一致 |

**M1 完成定义（DoD）**：G-5 落地后，用根脚本 `pnpm dev` 打开示例，能从空画布拖入节点、连线、删除、撤销到初始态；`pnpm test` 与 CI 全绿；`pnpm build` 通过。

### M2：节点体系与配置（约 10–14 人日）

| 编号 | 任务 | 验收标准 |
| --- | --- | --- |
| N-1 | 节点类型注册表（类型 → 图标/默认数据/锚点/参数 schema/渲染器） | 新增一种节点 ≤ 1 个文件，无需改内核 |
| N-2 | 6 类内置节点：开始、结束、大模型、插件、条件、代码 | 各自有图标、默认数据、锚点、参数 schema |

| N-4 | 配置面板：名称、描述、参数表单（string/number/boolean/select/json） | 修改立即反映到文档，重开面板值一致 |
| N-5 | 变量引用：`{{nodeId.field}}`，选择器按拓扑过滤上游 | 非法引用标红并阻止保存/运行 |
| N-6 | 输入/输出预览（类型 + 描述） | 面板能展示节点入参 schema |
| N-7 | 文档模型：`Workflow` schema、版本号、导出/导入、迁移函数 | 导出的 JSON 可重新导入并完整还原 |
| N-8 | 文档级校验：孤立节点、悬空连线、必填缺失、引用失效 | 生成问题列表，点击可定位节点 |
| N-9 | 示例应用升级：左节点面板（拖入画布）+ 三栏布局 | 示例即产品演示，覆盖主要交互 |

**M2 完成定义**：在示例中搭一个带条件分支的流程，改参数、引用上游变量、导出 JSON、重新导入后完全还原，校验面板无错误。

## 3. 依赖关系

```
G-1..G-6 工程地基
   ├─▶ C-1..C-3 视口
   │     └─▶ C-4..C-7 锚点 / 连线
   │           └─▶ C-8..C-9 选择 / 删除
   │                 └─▶ C-10 撤销 / 重做
   └─▶ N-1..N-3 节点注册表
         └─▶ N-4..N-6 配置面板
               └─▶ N-7..N-8 文档 / 校验
                     └─▶ R-1..R-6 运行调试
                           └─▶ D-1..D-5 交付
```

要点：

- **G-3（Hooks 修复）必须早于 C-8/C-10**，否则选择与历史栈会踩同一个坑；
- **N-7（文档模型）应早于 R-1**，Runner 直接消费 `Workflow` 文档；
- **D-1（构建）依赖 G-1/G-5**，不要在类型错误未清零时做发布。

## 5. 明确暂不做（防止范围蔓延）

| 能力 | 结论 | 理由 |

| 20+ 节点类型 | 不做 | 用注册表扩展，业务节点交宿主 |

## 7. 第二轮（M1 收口）范围提议

> 状态：**待负责人确认**（2026-11-03）。本轮只产出规划，不实现。
> 目标：让 M1 的完成定义成立，把"能画"变成"能编"。

### 7.1 为什么先收口 M1

M1 的 DoD 要求：用 `pnpm dev` 打开示例后，**能从空画布创建节点、连线、删除、撤销到初始态**。当前差距：

| DoD 要素 | 现状 |
| --- | --- |
| 从空画布创建节点 | ❌ 画布没有任何添加入口，节点只能由宿主 props 传入 |
| 连线 | ✅ 已完成 |
| 删除 | ❌ C-9 未做，画布上无法删除节点或连线 |
| 撤销到初始态 | ❌ C-10 未做 |

如果跳过这圈直接进 M2（节点注册表 + 配置面板），会得到一个"能配置但改坏了撤不回"的编辑器；而且注册表、配置面板本身的交互测试都缺少**选择**与**删除**这两个基础原语，M2 的测试只能直接操纵 store，验证不到真实交互。因此建议第二轮 = M1 收口。

### 7.2 范围

| 编号 | 任务 | 对应需求 | 验收标准 |
| --- | --- | --- | --- |
| R2-1 | 文档模型与变更原语前置 | FR-D1、FR-D2 | 新增 `Workflow` 快照类型（nodes / edges / viewport）；`applyNodeChanges` / `applyEdgeChanges` 支持 add / remove / replace / select / position；store 以单份文档状态为准。五类 change 均有单测 |
| R2-2 | 选择 | C-8、FR-D2 | 单击单选、Shift 追加/取消、点空白取消、Esc 取消；节点与连线共用 `selected`；触发 `onSelectionChange`。框选不做 |
| R2-3 | 删除 | C-9、FR-N5、FR-E5 | Delete / Backspace 删除选中节点及其关联连线；连线可单独选中删除；输入框内不触发。删除后无悬空连线，并有单测 |
| R2-4 | 撤销 / 重做 | C-10、FR-D4 | 快照式历史栈（默认容量 50）；一次拖拽合并为一条记录；创建/删除连线入栈；`Ctrl/Cmd+Z`、`Ctrl/Cmd+Shift+Z`；初始态不可再撤销 |
| R2-5 | 节点卡片视觉 | C-11、FR-N1 | 图标 + 标题 + 类型徽标 + 常态/悬停/选中三态；卡片尺寸与锚点几何同步调整（规格见 PRD Q7）；类型元数据先用内置常量表（注册表由 M2 的 N-1 接管） |
| R2-6 | 节点创建入口 | M1 DoD、N-9 前置切片 | 左侧最小节点面板（首版开始 / 大模型 / 结束，可扩到 6 类），点击或拖入画布创建节点；空画布即可用 |
| R2-7 | props 同步边界 | FR-X1 前置 | 修掉"宿主每次渲染传入新数组会把内部状态冲掉"的隐患（当前 `ReactFlow` 在 `useEffect` 里无条件同步）；明确 v1 暂用非受控 + 初始值语义，受控 `workflow` API 随 N-7 定 |
| R2-8 | 文档同步 | — | ROADMAP / PRD / README 与实现对齐；把 C-4 的"6 类节点锚点"明确排到 M2 |

### 7.3 明确不做

框选与多选浮动工具条（C-8 的 P1 部分）、复制粘贴、节点重命名、配置面板与变量引用（M2）、条件多出口与分支标签（N-3）、节点注册表（N-1）、文档导入导出（N-7）、运行调试（M3）。

### 7.4 完成定义

空画布 → 用面板创建三个节点 → 连线 → 选中节点与连线 → 删除 → 撤销回到初始态 → 重做；`pnpm test` / `typecheck` / `build` / `lint` 与 CI 全绿；PR 附同一场景的 Before / After 截图。

### 7.5 顺序与依赖

R2-1 最先做（否则 R2-4 要重写两次）。R2-2 → R2-3 → R2-4 依次推进：删除依赖选中，撤销依赖文档快照。R2-5 与 R2-6 可与 R2-2 并行；R2-7 在 R2-4 之后收口（两者都会改 store 的写入路径）。

### 7.6 工作量

6–9 人日（单人全职粗估，误差 ±50%）。

### 7.7 备选方案 B：直接进 M2

范围 = N-1 节点注册表 + N-2 六类节点 + C-4 + C-11，约 6–8 人日。

- **收益**：更早看到"6 类节点"的演示效果，注册表契约提前稳定。
- **代价**：M1 的 DoD 仍不成立——不能删、不能撤销，改错参数无法回退；注册表与配置面板的交互测试缺少选择/删除原语，只能直测 store。
- **建议**：除非当前首要目标是尽快对外展示节点体系，否则选方案 A（§7.2）。
